# U-Boot 실습별 실제 Claude Code 녹화

설명 슬라이드 영상은 제거했지만 U-Boot 실습 네 개에 실제 사용 장면이 없었다. 작은 C 예제 하나로는 실습의 분석·빌드·테스트·문서화 과정을 보여주기에 부족했다.

각 실습 제목 바로 아래에 실제 Claude Code 녹화를 배치했다. 설명 슬라이드는 클릭으로 넘기는 보조 자료로 접고, 기존 C 예제는 선택형 워밍업으로 이동했다.

| 실습 | 영상 | 확인한 실제 결과 |
|---|---:|---|
| 레거시 C 분석 | 36초 | 소스·커밋 확인, ECC/ready 흐름, MMIO와 계산 구분 |
| 빌드 | 29초 | da850 설정, ARM GCC, 드라이버 object 컴파일·ELF 확인 |
| 테스트 | 103초 | helper 추출, 경계값·5,000개 입력, mutant 실패, 별도 1-bit 설정 컴파일 |
| 문서화 | 75초 | Markdown 작성, 단위 오류 수정, 실제 빌드 명령 대조·재검사 |

U-Boot v2026.01 커밋 `127a42c7257a6ffbbd1575ed1cbaa8f5408a44b3`, Claude Code 2.1.274의 실제 대화형 터미널을 캡처했다. 화면 출력을 합성하지 않았다. 요청, 생성 코드, 적용 가능한 patch, 편집 구간과 재현법은 [세션 기록](../../demos/uboot-sessions/README.md)에 보존했다.

## 영상·내용 검토

- 신규 영상 243초를 1초 간격 243장, 장면표 14장으로 육안 확인했다. 긴 승인·응답 대기는 제거했고, 결과를 읽는 구간과 실제 오류·수정 장면은 남겼다. 보존 구간은 원래 순서·속도다.
- 기본 보드 설정은 4-bit ECC이므로 수정한 1-bit 분기는 별도 설정으로 컴파일했다. 전체 펌웨어 링크나 보드 동작을 검증했다고 표현하지 않는다.
- 생성된 mutation 검사에서 컴파일 실패를 성공으로 오인하는 문제를 수정하고 실제 SIGABRT를 확인하도록 재실행했다. 독립적인 컴파일 오류 주입에서도 실패 처리됨을 확인했다.
- 생성 문서의 “12바이트” 오류를 “24비트·3바이트”로 수정했다. 마지막 make는 기존 object 재검사로 명시했다.
- 테스트 원본 209~240초의 시스템 계정 정보는 전체 화면을 가렸다. 편집본에는 이 구간이 없다. 공개 원본·편집본의 SHA-256을 manifest에 기록했다.

## 검증

- `pnpm test`: 8개 파일, 13개 테스트 통과. 영상·원본 해시, 편집 길이·자막·포스터 확인.
- `pnpm exec tsc --noEmit`, `NEXT_PUBLIC_BASE_PATH=/claude-code-1hour pnpm build`: 통과.
- `scripts/audit/interactions.cjs`: 실습 영상 4개·워밍업 1개, 자막 로드, 수동 재생, 장면 탐색, 동시 재생 방지, 수동 슬라이드 9개 조작 통과.
- `scripts/audit/page.cjs`: 1440px·390px 화면에서 가로 넘침 없음. 섹션 활성 표시 14/14 일치. 실습 영역의 데스크톱·모바일 화면 확인.
- 기준 U-Boot 사본에 `git apply --check` 통과. 호스트 테스트 baseline exit 0, mutant SIGABRT(-6), 원본 helper 유지 확인.

로컬 화면·프레임 증거는 `.audit/practices/`에 보관하며 게시 산출물과 재현 코드는 저장소에 포함한다. 보드 부팅·NAND I/O·하드웨어 오류 주입은 이번 검증 범위에 포함하지 않았다.
