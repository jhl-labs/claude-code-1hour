# Claude Code 60분 강의 전수 점검 — 2026-09-17

**판정: 현재 자료는 그대로 최신 Claude 소개·실습 자료로 사용하기에 부족하다.** 모델명 일부는 최신이지만 사용 조건과 실제 사용법이 빠져 있다. 더 큰 문제는 모의 실행을 실측으로 설명하고, 영상과 본문이 서로 다른 드라이버를 보여주며, 검증되지 않은 테스트·빌드 성공을 확정적으로 전달한다는 점이다. 영상은 긴 정지 구간과 가독성 문제를 함께 수정해야 한다.

이번 산출물은 **점검 결과와 전체 개선 설계**다. 서비스 본문·영상 원본은 아직 수정하지 않았다. 검증된 사실, 코드에서 확인한 오류, 편집상의 권고를 구분했다.

## 1. 범위와 방법

- 기준 소스: Git HEAD `1e2652c`. `app/sections`의 7개 섹션, FAQ 10개, 모든 표시용 예제·표·프롬프트·영상 큐를 읽었다.
- 활성 영상: Remotion 9개 + `public/videos` MP4 5개 = **14개, 총 851.92초(14분 11.92초)**. Hero 장식 루프 15초를 포함한 한 번씩의 재생시간이다.
- MP4는 ffprobe로 길이·코덱·오디오 유무·SHA-256을 기록하고 ffmpeg로 1초 간격 추출. Remotion은 실제 활성 composition을 30프레임마다 렌더링했다.
- **851장, 타임스탬프가 있는 장면표 48장을 모두 육안 점검**했다. 이는 모든 영상을 초 단위로 살폈다는 뜻이며, 25/30fps의 모든 원본 프레임을 검사했다는 뜻은 아니다. 1초보다 짧은 순간적인 문제는 추가 검사가 필요하다.
- 픽셀 변화량으로 정지 후보를 구한 후 화면 내용·애니메이션 코드와 대조했다. 작은 커서 변화나 타이머 변화는 새 학습 내용으로 세지 않았다. 정지 후보를 전부 불필요한 대기로 단정하지 않았다.
- 로컬 웹 페이지를 Chrome의 1440×1000, 390×1000 뷰포트에서 확인했다. 원본 Remotion 렌더와 웹 Player는 CSS 영향이 다를 수 있어 레이아웃 지적에는 범위를 표시했다.
- 공개 사이트 HTML은 응답을 확인했다. 배포된 모든 자산의 해시를 로컬과 대조한 감사는 아니다.
- 제품 정보는 점검일의 Anthropic·Claude Code 공식 문서와 대조했다. 실제 유료 Claude 세션, U-Boot 크로스 빌드, 하드웨어 계측을 새로 수행한 것은 아니다.
- `pnpm test`: **6개 파일 / 10개 테스트 통과**. `pnpm typecheck:remotion`: **통과**. 이 결과는 페이지·영상 내용의 사실성이나 U-Boot 테스트 성공을 입증하지 않는다.

### E 테스트의 구체적인 오류

`demos/outputs/E-unit-test.txt`는 다음 순서다.

1. `nand_davinci_calculate_ecc(NULL, buf, ecc_calc)`.
2. `memcpy(ecc_read, ecc_calc, 3)`.
3. `buf`의 비트를 뒤집는다.
4. 변경되지 않은 동일한 두 ECC 배열을 `nand_davinci_correct_data()`에 전달한다.
5. 1bit 보정 또는 `-EBADMSG`를 기대한다.

대조한 [U-Boot v2026.01 원본 드라이버](https://github.com/u-boot/u-boot/blob/v2026.01/drivers/mtd/nand/raw/davinci_nand.c)는 ECC 차이가 없으면 0을 반환한다. calculate 함수도 buffer를 소프트웨어로 계산하는 구현이 아니라 컨트롤러 레지스터를 읽는다. 따라서 제시한 코드만으로 해당 PASS를 정당화할 수 없다. 여기에 static 함수의 외부 접근, NULL 장치 인자, 실제 MMIO와 연결되지 않은 mock 문제가 겹친다. 원본 대조 사본은 `.audit/before/davinci_nand-v2026.01.c`에 있다. 영상이 사용한 정확한 U-Boot 커밋은 기록되어 있지 않으므로 모든 버전의 동작을 동일하다고 단정하지는 않는다.

### 재현성 결함

`clone-uboot.sh`는 고정 커밋 없이 shallow clone한다. tape는 `/tmp/lecture-demo`, `.claude-resp/*.txt`에 의존하며 해당 생성 과정이 일관되게 추적되지 않는다. 대체 렌더러는 실제 shell 없이 scene/output 텍스트로 영상을 합성한다. 녹화 출력 경로와 `public/videos`의 배포 자산 사이에도 단일 manifest가 없다. “같은 소스를 다시 실행하면 같은 내용의 영상이 만들어지는가”를 현재 기록만으로 보장할 수 없다.

- 단순히 전체 2배속으로 만들지 않는다. 이미 표·코드가 빠르게 스크롤하는 구간은 오히려 확대·분할·정지가 필요하다.

| 4 | 최신 기능과 시작 경로 보강 | 모델 선택·인증·권한·메모리·비용·Workflow 구분을 실습과 연결. 최신 확인일과 공식 문서 링크 포함. |
| 5 | 영상 재구성 | 위 영상별 목표를 출발점으로 편집. 1초 프레임 재검토, 장면별 큐 검증, 대기와 읽기 시간 균형 확인. |
| 6 | 페이지 배치·목차 수정 | 데스크톱/모바일에서 읽을 수 있고 모든 섹션 추적 정상. 자동재생·pause·reduced-motion·확대 동작 검증. |
| 7 | 통합 검증과 공개 준비 | 기존 테스트·타입 검사·빌드, cue≤duration 검사, 실제 데모 실행, 최신 문서 재확인, 최종 이미지 리뷰. |

실제 재촬영에 필요한 것은 비밀번호 공유가 아니라 사용할 Claude 계정/조직 정책에 맞는 실행 환경과 검증 대상이다. 현재 저장소만으로 실제 성공 로그나 성능 수치를 새로 만들어 낼 수는 없다. 모의 교육 영상으로 유지하는 선택도 가능하지만 실제 성능 입증이라는 주장은 내려야 한다.

권장 60분 구성은 다음과 같다. 긴 역사와 반복 효과 영상을 줄여 안전한 첫 실행과 실제 검증에 시간을 배분한다.

| 시간 | 내용 | 청중이 확인할 결과 |
| --- | --- | --- |
| 0~5분 | Claude / Code / 최신 모델과 이용 조건 | 무엇을 설치하고 어떤 모델을 쓸지 구분 |
| 5~13분 | 설치·인증·권한·첫 읽기 작업 | 자신의 저장소에서 변경 없이 분석 시작 |
| 13~23분 | 지침·메모리·context·도구 실행 | 지침과 강제 정책, 실행과 검증의 차이 이해 |
| 23~43분 | A/C/E/H 실제 검증 데모 | 근거 있는 분석·빌드·테스트·문서화 결과 확인 |
| 43~50분 | Skill·Subagent·Workflow·MCP 확장 | 각각 언제 쓰는지와 설치·권한 전제 구분 |
| 50~55분 | 비용·데이터·검토 체크리스트 | 팀에 적용할 첫 과제와 성공 기준 선택 |
| 55~60분 | Q&A | 실제 환경의 제약 해결 |

## 8. 이후 유지 관리

- 모델·기능 문구마다 확인일과 공식 출처를 관리한다. 강의 전 다시 확인하고 오래된 영상을 현행 버전처럼 표기하지 않는다.
- 영상 manifest에 ID, 종류, 원본 길이, 표시 길이, 해시, 큐, transcript, 데모 실행 근거 경로를 둔다.
- 기존 문자열 테스트의 “모델명이 들어 있는가”만으로 최신성을 판단하지 않는다. 잘못된 cue, 실제로 보이지 않는 결론, 읽을 수 없는 영상 크기 같은 사용자 관점 검증을 추가한다.
- 향후 성능 비교는 동일 과제·난이도·완료 기준, 사람 검토·재작업 포함 시간, 여러 회차, 실패 사례를 함께 공개한다.
